## 🔥 What is Redis?

**Redis (Remote Dictionary Server)** is an **in-memory key–value database**.

### 👉 Simple Definition:

Redis stores data in **RAM (memory)** instead of disk, which makes it **extremely fast**.

---

## ⚡ Why Redis is Fast?

* Data is stored in RAM (not disk)
* No heavy disk I/O operations
* Optimized for quick read/write

👉 Result: **microsecond-level performance**

---

## 🧠 Redis vs MongoDB (Important)

| Feature        | Redis                        | MongoDB                    |
| -------------- | ---------------------------- | -------------------------- |
| Type           | Key-Value Store              | Document Database          |
| Storage        | In-memory (RAM)              | Disk-based                 |
| Speed          | Extremely Fast 🚀            | Fast but slower than Redis |
| Use Case       | Caching, sessions, tokens    | Persistent data storage    |
| Data Structure | Strings, Lists, Sets, Hashes | JSON-like documents        |
| Persistence    | Optional                     | Default                    |

### 💡 Real-world usage:

* MongoDB → store users, posts, data
* Redis → store **temporary data** like:

  * sessions
  * cache
  * blacklisted tokens

## 📁 Step 3: Middleware (auth.middleware.js)

### ❌ Problem in Your Old Code:

You were checking blacklist in MongoDB (slow ❌)

### ✅ New Code using Redis:

```js
const jwt = require("jsonwebtoken");
const redis = require("../config/cache");

async function authUser(req, res, next) {
  const token = req.cookies.token;

  if (!token) {
    return res.status(401).json({ message: "Token not provided" });
  }

  try {
    // 🔥 Check Redis first (FAST)
    const isBlacklisted = await redis.get(token);

    if (isBlacklisted) {
      return res.status(401).json({ message: "Invalid Token" });
    }

    // Verify token
    const decoded = jwt.verify(token, process.env.JWT_SECRET);

    req.user = decoded;
    next();
  } catch (err) {
    return res.status(401).json({ message: "Invalid token" });
  }
}

module.exports = { authUser };
```

---

### 🔍 Step-by-step Flow:

1. Extract token from cookies
2. Check Redis → `redis.get(token)`
3. If exists → ❌ reject
4. If not → verify JWT
5. Attach user → `req.user`
6. Continue request

## 📁 Step 4: Auth Controller

### 🔥 Logout Logic (IMPORTANT)

### ❌ Your Previous Approach:

* Stored token in MongoDB (slow)

### ✅ New Redis Approach:

```js
async function logoutUser(req, res) {
  const token = req.cookies.token;

  if (!token) {
    return res.status(400).json({ message: "No token found" });
  }

  // Remove cookie from client
  res.clearCookie("token");

  // 🔥 Store token in Redis (Blacklist)
  // EX = expiry time (seconds)
  await redis.set(token, "blacklisted", "EX", 60 * 60 * 24 * 3);

  return res.status(200).json({
    message: "User logged out successfully",
  });
}
```

---

### 🔍 Why we added `EX`?

👉 `EX` = Expiry time

* JWT expires in **3 days**
* So Redis key should also expire in 3 days

Otherwise:

* Redis memory will keep growing ❌

```js
const jwt = require("jsonwebtoken");
const redis = require("../config/cache");

async function authUser(req, res, next) {
  const token = req.cookies.token;

  if (!token) {
    return res.status(401).json({ message: "Token not provided" });
  }

  try {
    // 🔥 STEP 1: Redis check
    const isBlacklisted = await redis.get(token);

    if (isBlacklisted) {
      return res.status(401).json({ message: "Invalid Token" });
    }

    // 🔥 STEP 2: JWT verify
    const decoded = jwt.verify(token, process.env.JWT_SECRET);

    // 🔥 STEP 3: Attach user
    req.user = decoded;

    next();
  } catch (err) {
    return res.status(401).json({ message: "Invalid token" });
  }
}

module.exports = { authUser };
```
